Convert QIF transactions to CSV

QIF stands for Quicken Interchange Format. It is a text-based format used to exchange financial records between personal-finance programs and other tools. A QIF file is not arranged like a normal spreadsheet: transaction details appear as short, tagged lines, and a marker separates one transaction from the next. Converting QIF to CSV places the recognised transaction fields into rows and columns that spreadsheet software can open and that other systems may be able to import.

How to convert a QIF file

  1. Select your local .qif file, or paste its text into the statement box.
  2. Select Convert to CSV and wait for the status message reporting the result.
  3. Review the preview, then choose Download result to save the transaction table as a CSV file.

Loading a file does not start conversion automatically. If you edit the text after loading it, convert again before downloading. The sample option is useful for seeing the expected layout, while Clear removes the current input and output. Keep your original statement until you have checked the exported data.

Which transaction details are included?

The CSV output uses columns for date, amount, payee, memo, category, account type, transaction type, check number, cleared status, and ID. Values are populated when the corresponding information is present in the QIF record and recognised by the converter. Many transactions will not have every field, so blank cells do not automatically indicate an error. The account type is based on the QIF type header when supplied.

CSV is a plain-text table, not a full copy of the QIF structure. The converter focuses on transaction-level fields rather than preserving every original line or all application-specific metadata. In particular, split-category details are not expanded into separate rows by this converter. If a transaction allocates one payment across several categories, compare it with the source before relying on category totals or reports.

Common issues with QIF files

The converter expects a QIF-style header such as !Type: or !Account. If the file is actually a different export format that has merely been given a .qif extension, it may not be interpreted correctly. Open the file in a text editor and check that it contains recognisable QIF tags and transaction separators. Empty or truncated files may produce no useful rows.

QIF variants can differ between applications and account types. Dates may use different conventions, and text fields may contain characters or line breaks that deserve extra attention. Inspect a few transactions from the beginning, middle, and end of the file. Check that the expected payees and memos appear, that amounts retain their signs, and that records have not been accidentally combined or omitted.

Check the CSV in your spreadsheet

When opening CSV in spreadsheet software, confirm how dates and decimal values are interpreted. Spreadsheet programs may automatically reformat dates or treat long numeric-looking identifiers as numbers. If a value is important as an exact text identifier, preserve it as text during import. Also compare the number of exported transactions and selected totals with the source application. A CSV can be syntactically valid while still needing a business-level review.
