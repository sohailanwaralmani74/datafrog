Turn an XML file into usable JSON

Have an XML export, product feed, RSS file, or data document that you need in JSON? Load the XML above, review the text, choose how attributes should appear, and convert it. You can then copy the result into another tool or download a .json file. You do not need to retype nested records by hand.

When this conversion helps

  • Moving product or inventory data: turn repeated product elements into JSON records that are easier to pass to another data workflow.
  • Working with XML feeds: convert an RSS, Atom, or other XML document when the next tool expects JSON. Check namespace-heavy feeds after conversion because element names are kept as the parser sees them.
  • Inspecting nested records: make parent-child relationships visible as nested objects instead of searching through long XML markup.
  • Preparing data for a JSON-based workflow: create a starting JSON file, then review field names and value types before importing it elsewhere.

How to get the result you need

  1. Choose an XML file or load the sample catalog to see the output format.
  2. Review the editable XML text. If the file contains an error, correct the markup before converting.
  3. Choose an attribute prefix: @ keeps attributes distinct, _ uses an underscore, and None uses the attribute name without a prefix.
  4. Leave automatic number and boolean conversion enabled if values such as 24 and true should become JSON numbers and booleans. Turn it off if those values must remain text, such as an identifier with leading zeroes.
  5. Select Convert to JSON, inspect the output, then copy or download it.

Example: repeated XML records

Several sibling elements with the same name, such as multiple <product> elements, are represented as an array in the resulting JSON. That is useful when a feed contains a list of products, orders, or entries. A single element may instead appear as one object or value, so check the shape if another system expects an array every time.

Check these details before using the JSON

  • Numbers that look like text: automatic conversion can change values such as postal codes, account numbers, or product codes. Disable coercion when the exact text matters.
  • Attributes and child elements: attributes become object properties, while nested tags become child properties. Review the chosen prefix if names overlap.
  • Mixed content: text and child elements in the same XML element need careful review; do not assume every document maps perfectly to a simple object.
  • Namespaces and special XML features: inspect the output for namespaced tags, comments, processing instructions, and document-specific conventions before relying on it.
  • Large or important files: compare a few records against the original, especially before importing converted financial, inventory, or customer data.

Frequently asked questions

Can I convert an XML file without installing software?

Yes. Open the page in a modern browser, select your file, and convert it there. The file is read in your browser rather than uploaded to a conversion server.

Why did a value become a number instead of text?

Automatic type conversion is enabled by default. Turn it off when numeric-looking values must remain exact strings, especially identifiers with leading zeroes.

What should I do if conversion fails?

Read the XML error, correct unclosed tags, invalid nesting, or unescaped special characters in the editable input, and convert again.
