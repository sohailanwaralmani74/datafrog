Get XML records into a spreadsheet-friendly CSV

If an application gave you an XML export but you need rows and columns, start by loading the file above. Review or edit the XML text, convert it, and copy or download the CSV output for a spreadsheet or another data tool. This is most useful when the XML contains a repeated set of records with similar fields.

Good reasons to convert XML to CSV

  • Open exported records in a spreadsheet: turn repeated items, contacts, products, or transactions into a table you can sort and review.
  • Share data with a tool that accepts CSV: create a simpler interchange file when the receiving application does not accept XML.
  • Check a feed or report: put similar values into columns so missing fields and unexpected values are easier to spot.
  • Prepare a one-time data import: create a CSV draft, then confirm the receiving system's required column names and format.

Convert the file in a few steps

  1. Select an XML file or use the sample to see how the output is arranged.
  2. Review the XML input and correct any malformed tags or unescaped characters shown by the parser.
  3. Run the conversion and inspect the resulting rows and columns before downloading.
  4. Open the CSV in your spreadsheet application and check the delimiter, headers, and a few records.

XML is hierarchical; CSV is a table

XML can contain nested elements, attributes, and repeating groups. CSV has a flat row-and-column structure. That means a conversion cannot preserve every relationship in the same way as the original XML. A file with repeated records is usually a better fit than a document whose main purpose is to represent deeply nested relationships.

Before converting a complex file, decide which element represents one row and which values you need as columns. If the XML contains a customer with several orders, for example, you may need one row per order and repeated customer details, or separate files for customers and orders. Review the output rather than assuming the hierarchy has been preserved.

Avoid common CSV surprises

  • Commas, quotes, and line breaks: these can occur inside values. Check that the output quotes and escapes such values so they remain in the correct cell.
  • Missing fields: XML records may not all contain the same tags. Review rows with blanks before importing them elsewhere.
  • Repeated child elements: multiple values inside one record may not fit neatly into a single cell. Confirm how those records appear in the result.
  • Leading zeroes and long numbers: spreadsheet software may reinterpret CSV values. Import the file as text when exact identifiers matter.
  • Namespaced or specialized XML: inspect representative records, especially if the source is a standards-based feed or export.

Frequently asked questions

Can I open the CSV in Excel?

Yes. Download the CSV and open or import it in Excel or another spreadsheet app. Check column types during import if identifiers or dates must retain their original text.

Will every XML structure convert cleanly to a table?

No. CSV is flat, so deeply nested or irregular XML needs review. Confirm that the chosen rows and columns preserve the fields your next workflow requires.

Are my XML files uploaded?

The conversion runs in your browser. Your selected file is read locally by the page rather than sent to a conversion server.
